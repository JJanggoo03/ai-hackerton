# 취업 질문과 과제 질문의 답변 구분

!취업정보 또는 !잡코리아 선택 시 질문 내용으로 다음 유형을 구분한다. 선택하지 않으면 기존 일반 답변 경로를 유지한다.

| 질문 예시 | 답변 방식 |
|---|---|
| 삼성전자 합격 스펙·취업 가능성·자소서 사례를 알려줘 | 실제 수집한 통계와 사례 우선. 합격 가능성은 본인 정보와 비교하되 확률을 지어내지 않음 |
| 이 과제를 취업에 유리하게 보완하려면? | 과제 설명 뒤 실제 사례와 연결해 추가를 권장 |
| 이 과제의 코드 초안을 만들어줘 | 실제 초안 작성 후 초안에 반영한 요소만 추가했다고 설명 |

기업 질문에서는 통계와 자소서 자료를 우선 확보한다. 긴 후기나 보관함의 R·회귀분석 내용이 통계를 밀어내거나 기업의 필수 스펙으로 둔갑하지 않도록 자료 예산과 지시를 구분했다. 과제 생성은 현재 답변 안의 초안이며 파일·GitHub에 자동 저장하는 기능은 아니다.

화면에 표시하는 '수집한 합격자 통계' 표는 모델이 작성한 숫자가 아니라 실제 반환 본문의 항목별 평균·보유율에서 추출한다. 예를 들어 평균3.72/4.5와 보유율86%는 '86%가3.72이상'이라는 의미가 아니다. 평균 횟수·개수에도 '이상'을 붙이지 않는다. 보유율·평균·원문 통계 갱신일·출처를 분리해 표시한다. 수집에 실패한 통계는 만들지 않는다.

자소서 사례는 읽은 목록 발췌의 직무·연도·문항 요지·경험 흐름을 요약한다. 상세 원문을 읽지 않았다면 전체를 읽었다고 말하지 않는다. 사례와 통계는 현재 기업의 공식 지원요건·가산점·합격선이 아니다.

적용: 우리 보관함 서버 재시작 후 Ctrl+F5. 이 변경은 우리 서버·화면에 적용하며 친구 Python 서버의 추가 교체는 필요 없다.

검증: Node 전체49통과/기존PG API통합1skip. 실제 친구 서버의 삼성전자 통계10항목·자소서 발췌를 사용하고 가상 로컬 과제로 질문했을 때 기업정보 모드와 수치·사례 답변을 확인했다. 사용자 보관함·GitHub 원본은 검증에 사용하지 않았다.

추가 검증에서 모델이 코드 설명의 출처를 반복하거나 과제의 R 기술을 기업 필수요건처럼 표현하는 경우를 관측했다. 코드블록·인라인 코드를 보존하며 반복 인용을 정리하고, 공식 공고가 없는데 특정 기업의 필수요건으로 단정하는 문장은 제외하도록 보완했다. 실제 생성된 코드에서 확인한 MAE/RMSE 계산 등만 반영 완료 문구로 설명한다. 코드가 생성되지 않았다면 추가했다고 자동 표시하지 않는다. 생성한 코드는 실행 검증한 완성물이 아니라 초안이다.
